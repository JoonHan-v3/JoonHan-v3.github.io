Robotics Lawn Mower — Version 4

A full simulation of a GPS-guided autonomous lawn mower built with ROS 2 and Gazebo. The differential-drive robot autonomously covers a GPS-defined lawn using a serpentine coverage path while wheel odometry, GPS, and IMU data are fused through dual EKFs for accurate local and global localization. Nav2 handles path following and lidar-based navigation, while a custom coverage planner generates mowing paths for non-convex lawn boundaries. An obstacle-aware coverage executor continuously monitors the global costmap, dynamically replans around detected obstacles, and rejoins the original mowing path to continue coverage with minimal skipped area.

  • Robotics: ROS 2 Jazzy, Gazebo Harmonic (gz-sim8), ros_gz bridge, RViz
  • Navigation: Nav2, Regulated Pure Pursuit, NavFn, FollowPath, behavior trees, layered costmaps
  • Localization: robot_localization dual EKF, navsat_transform_node, wheel odometry, simulated GPS and IMU
  • Perception & Replanning: lidar, global costmap, obstacle detection, dynamic path replanning and recovery
  • Coverage Planning: GPS boundary conversion, Shapely, boustrophedon/serpentine coverage planning, non-convex polygons
  • Languages/Tools: Python (rclpy), Shapely, pymap3d, URDF/Xacro, SDF, colcon/ament

Robotics Lawn Mower — Version 3

A full simulation of a GPS-guided autonomous lawn mower: a differential-drive robot with a spinning cutting deck that surveys a GPS-defined boundary, plans a complete coverage path, and mows the entire lawn unattended. Wheel odometry, simulated GPS, and IMU are fused through a dual EKF into a persistent global frame, giving the robot an absolute sense of position on the field rather than a drifting local estimate. A Nav2 stack handles path following and lidar-based obstacle avoidance, and a custom boustrophedon planner generates the back-and-forth mowing pattern from the surveyed boundary polygon.

  • Robotics: ROS 2 Jazzy, Gazebo Harmonic (gz-sim8), ros_gz bridge
  • Navigation: Nav2 (Regulated Pure Pursuit controller, NavFn global planner, behavior tree navigator, lifecycle management, layered costmaps)
  • Localization: robot_localization dual EKF (local odom + global map), navsat_transform_node, GPS/IMU/lidar sensor simulation
  • Languages/Tools: Python (rclpy), Shapely, pymap3d, URDF/Xacro, SDF, colcon/ament

Tiny YOLO SAM — Zero-Shot Instance Segmentation via Detection-Guided Prompting

A pipeline that composes a real-time object detector with a distilled Segment Anything model to get pixel-accurate instance masks without any segmentation-specific training. YOLOv12 proposes class-labeled bounding boxes for a scene; each box, together with its center point, is fed to TinySAM (a knowledge-distilled, quantization-friendly SAM variant) as a prompt, which returns the best-scoring mask candidate per detection. Predicted boxes are remapped from YOLO's 80-class label space back to official COCO category IDs so the composed detector+segmenter can be scored end-to-end, zero-shot, against the COCO val2017 instance segmentation benchmark (5,000 images) via pycocotools AP/AR — measuring how much mask quality survives when box prompts come from a live detector instead of ground-truth boxes.

  • Pipeline: YOLOv12 box detection & COCO category-ID remapping, box+center-point prompting into TinySAM (best-mask selection by predicted IoU score), pycocotools COCOeval zero-shot scoring on val2017
  • Models: YOLOv12x (customized ultralytics fork), TinySAM vit_t (tinysam_42.3.pth distilled SAM checkpoint)
  • Languages/Tools: Python, PyTorch, OpenCV, pycocotools, CUDA/CPU auto-dispatch

LLM-APR Pipeline — Automated Security Vulnerability Repair

A research pipeline that asks whether LLMs can autonomously patch real-world security vulnerabilities in C/C++ codebases. Each vulnerability is sourced from the ARVO dataset as a Docker container with the vulnerable source, a crashing proof-of-concept input, and a sanitizer report. Clang tooling extracts the implicated functions and call graph, an LLM performs semantic analysis and root-cause localization, and a dialogue-based prompting chain generates candidate patches that are compiled and replayed against the original crash inside the container to confirm the fix. Four ablated pipeline variants isolate which reasoning stages (root-cause localization, semantic analysis, explicit patching strategy) actually move the needle, benchmarked across 18 real vulnerabilities in libexif and libplist.

  • Pipeline: Clang/LLVM LibTooling (call-graph & function extraction), Docker/ARVO sandboxed patch testing, multi-stage LLM dialogue (analysis → localization → strategy → patch), model-escalation retry loop (GPT-4.1-nano → mini → full)
  • LLM/APIs: OpenAI API (GPT-4.1 family), tiktoken
  • Languages/Tools: Python, C/C++, CMake, Bash, jq, docker SDK for Python
